GATE 1 Spec → Plan Validação da Especificação
⏱ SLA: 1 dia util após entrega do requirements.md
📁 Artefato gatilho: requirements.md
🔍 O que verificar
  • Cada requisito tem critério de aceite verificável e não ambíguo obrigatório
  • Todos os módulos afetados estão identificados (RAG pipeline, bot Teams, painel web)
  • Spec não contradiz nenhum ADR existente (ADR-0001 a ADR-0004) obrigatório
  • Escopo está dentro do que foi validado no Discovery — sem feature creep
  • Requisitos não-funcionais estão incluídos (latência, segurança, limites de tokens) obrigatório
  • QA validou testabilidade dos critérios de aceite antes da aprovação
  • Dev Pleno leu o requirements.md e levantou dúvidas de domínio

✅ Se aprovar — próximos passos
  • Tech Lead inicia elaboração do plan.md com Claude/Copilot
  • DM atualiza status no Azure DevOps — task "Spec" → Done
  • DM registra data/hora de aprovação e archiva o requirements.md aprovado
  • Dev Sênior e Pleno notificados de que o plano está em elaboração
❌ Se reprovar — protocolo
  • TL documenta itens reprovados com comentários objetivos no PR / documento
  • Product Specialist revisa spec com base nos comentários — sem reescrever do zero
  • Nenhuma linha de plan.md é iniciada até re-aprovação
  • DM ajusta prazo no board e registra motivo do bloqueio
  • Nova rodada de review em até 4h úteis após entrega da revisão
🔒 BLOQUEANTE — plan.md não pode ser iniciado
⏱ 1 dia útil · DM escala para o gestor se SLA for ultrapassado

GATE 2 Tasks → Implement Validação das Tasks Geradas por IA
⏱ SLA: 4 horas uteis após entrega do tasks.md
📁 Artefato gatilho: tasks.md
🔍 O que verificar
  • Cada task é atômica — concluível em no máximo 1 dia útil obrigatório
  • Toda task tem critério de "done" explícito e verificável obrigatório
  • Existe task de teste correspondente para cada task de implementação obrigatório
  • Dependências entre tasks estão mapeadas e não criam bloqueio circular
  • Nenhuma task exige decisão arquitetural ainda não resolvida em ADR
  • Tasks fazem sentido para o Dev Pleno (não apenas para o Sênior)
  • Cobertura total do plan.md — nenhum módulo ficou sem tasks
  • Tasks foram criadas no Azure DevOps pelo DM após geração pela IA

GATE 3 Código gerado por agente → Merge Code Review — PR Obrigatório
⏱ SLA: 24 horas uteis após abertura do PR
🔗 Mecanismo: Branch protection rule no GitHub (1 approval obrigatório)
🔍 O que verificar
  • Código segue as coding standards definidas no AGENTS.md do repositório obrigatório
  • Dev leu e entende o código gerado pela IA — não é "vibe coding" obrigatório
  • Testes unitários presentes e todos passando no CI obrigatório
  • Sem credenciais, connection strings ou dados hardcoded obrigatório
  • Tipos TypeScript corretos — sem any não justificado por comentário
  • Descrição do PR explica contexto, decisões tomadas e limitações conhecidas
  • Código está dentro do escopo da task — sem funcionalidade extra não aprovada
  • Logs e tratamento de erro adequados para o pipeline Azure Functions
  • QA revisou cobertura de testes e cenários de falha do Discovery no PR

GATE 4 Testes gerados por IA → Deploy Validação de Suficiência de Testes
⏱ SLA: 4 horas uteis após pipeline CI verde
📊 Threshold: ≥ 80% cobertura nas camadas de serviço
🔍 O que verificar
  • Todos os cenários de falha mapeados no Discovery estão cobertos obrigatório
  • Testes de integração passando — incluindo mock de Azure AI Search obrigatório
  • Casos de alucinação e chunks contraditórios testados (Anexo B) obrigatório
  • Cobertura de testes ≥ 80% nas camadas de serviço (relatório de coverage) obrigatório
  • Nenhum teste e2e crítico falhando obrigatório
  • Testes gerados pela IA foram revisados por humano — não apenas "gerados e commitados"
  • Smoke test manual executado em staging pelo QA antes da aprovação
  • Product Specialist validou comportamento funcional via demo ou painel web
